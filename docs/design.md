# Design

How arm-tools is built. Each section has a **Status** line; update it in the change that moves it. Milestones are in [roadmap.md](roadmap.md).

## Goals

- An editor experience for AArch64 assembly on macOS as good as for a high-level language: errors as you type, docs on hover, navigation, completion, rename.
- A linter that catches the bugs assembly programmers actually ship: ABI violations, broken address materialization, stack misalignment, clobbered registers.
- One source of truth for both. A rule written once runs in the editor and in CI.

Non-goals for now: AArch32 and Thumb, ELF and GNU-only syntax, x86, assembling or linking.

## Architecture

**Status:** Workspace in place (2026-10-26).

```
           text
            │
   ┌────────▼────────┐      ┌──────────┐
   │  syntax         │      │  isa     │  instruction tables
   │  lex → parse    │      │          │  (generated)
   └────────┬────────┘      └────┬─────┘
            │ lossless tree      │
            └────────┬───────────┘
            ┌────────▼────────┐
            │  sema           │  symbols, macros, includes,
            │                 │  sections, operand checks
            └────────┬────────┘
            ┌────────▼────────┐
            │  lint           │  rules over sema (+ CFG later)
            └───┬─────────┬───┘
         ┌──────▼──┐   ┌──▼──────┐
         │ armls   │   │ armtool │
         └─────────┘   └─────────┘
```

Every layer produces diagnostics in one shared shape: a byte range, a severity, a message, a code (`syntax`, `operand`, or a lint rule ID), and optional fixes. `armls` converts them to LSP diagnostics; `armtool` prints them.

## Syntax

**Status:** Done (2026-10-26). The grammar is in [0011](decisions/0011-parser-grammar.md) and [0012](decisions/0012-parser-survey-fixes.md).

The lexer turns text into tokens that cover every byte, including whitespace and comments. The parser builds a lossless, error-tolerant tree ([0008](decisions/0008-lossless-syntax-tree.md)), so the formatter can reproduce the file and the server can work on half-typed code.

Apple's assembler (LLVM's `AsmLexer` with `AArch64MCAsmInfoDarwin`) decides the lexical rules. Probed with clang 21 ([0004](decisions/0004-apple-aarch64-first.md)):

| Input | Meaning |
|---|---|
| `;` to end of line | comment |
| `//` to end of line | comment |
| `/* ... */` | comment, may span lines |
| `#` as the first non-blank on a line | comment (also cpp line markers) |
| `#` elsewhere | immediate prefix: `#1` |
| `%%` | statement separator |
| newline | statement separator |
| `@` | symbol variant: `_g@PAGE`, `_g@PAGEOFF`, `_g@GOTPAGE` |
| `1f`, `2b` | reference to the next or previous local numeric label |
| `:lo12:sym`, `%pltpcrel(sym)` | ELF relocation specifiers: parsed, but clang fails writing Mach-O, so sema reports them |
| `name .req x5` | register alias |

A file is a list of lines, and a line is a list of statements. A statement is a label, a directive (`.text`, `.globl _main`), an instruction (`mov x0, #1`), or a macro call. Operands are parsed into a small expression grammar: registers, immediates, shifts and extends, memory operands (`[x0, #8]!`), register lists (`{v0.4s, v1.4s}`), symbol references with variants, and arithmetic expressions.

Expressions follow LLVM's Darwin precedence, probed by evaluating expressions with clang: `* / %`, then `+ -`, then `<< >>`, then comparisons, then `| ^ &`, then `&& ||`. So `1 << 2 + 1` is 8.

Mnemonics and register names are case-insensitive. Symbol and macro names are case-sensitive.

Directive arguments parse leniently; sema checks each directive's form ([0011](decisions/0011-parser-grammar.md)). A call to a macro defined earlier in the file is a `MacroCall`, and the bodies of `.macro`, `.rept`, `.irp`, and `.irpc` aren't checked until expanded, as in clang ([0012](decisions/0012-parser-survey-fixes.md)). A full parse of a 10,000 line file takes about 2.6 ms.

`cargo xtask survey` checks the parser against clang on any directory of `.s` files. On LLVM's 2,383 AArch64 MC tests and the HelloSilicon code, every line we report is one clang rejects.

## ISA

**Status:** Tables generated (2026-10-26): 20,864 forms, 1,659 mnemonics, 1,025 operand classes, 635 register names, from clang's assembler matcher ([0013](decisions/0013-isa-from-llvm-tablegen.md), [0014](decisions/0014-isa-from-asm-matcher.md)). Operand matching done ([0017](decisions/0017-operand-matching.md)): clang's operand model, 378 of 385 predicates ported, 0 disagreements with clang on 2,352 files.

`arm-isa` knows every A64 instruction: its mnemonic, operand forms, which register classes and widths each slot takes, immediate ranges and alignments, the architecture feature it needs (for example `FEAT_LSE`), and a short description for hover. The tables are generated by `cargo xtask gen-isa` from LLVM's TableGen records and checked in, so building needs nothing but Cargo. Descriptions are written by us, since Arm's openly licensed spec has no prose ([0013](decisions/0013-isa-from-llvm-tablegen.md)).

A form is a mnemonic and a sequence of operand classes, exactly as clang's matcher sees them. Memory operands are flattened into tokens, so `ldp x0, x1, [sp, #16]!` is `GPR64, GPR64, [, GPR64sp, SImm7s8, ], !`. Matching an instruction means turning its operands into clang's operand model, then trying each form in order with clang's subclass rules and predicates. The first near miss gives clang's message ("index must be a multiple of 8 in range [-512, 504].").

Apple-specific facts live here too: x18 is reserved, x29 is the frame pointer, and which features each Apple core supports (M1 is Armv8.5-A plus extras; later cores add more).

## Sema

**Status:** Per-file model done (2026-10-26): symbols, references, block structure, and clang's semantic errors ([0015](decisions/0015-sema-file-model.md)). Includes done ([0019](decisions/0019-includes.md)). Conditional assembly done ([0023](decisions/0023-conditional-assembly.md)). Macro and repeat expansion done ([0024](decisions/0024-macro-expansion.md)).

Built from the tree for one file plus what it includes:

- **Symbols:** labels, `.globl`/`.private_extern`, `.set`/`.equ`, with their definition and every reference.
- **Local numeric labels:** `1:` resolved for `1f` and `1b`.
- **Macros:** `.macro`/`.endm` definitions, their parameters, and expansion for checking. `.rept`, `.irp`, `.irpc`.
- **Conditional assembly:** `.if`, `.ifdef`, `.else`, `.endif`. Inactive branches are greyed out, not checked.
- **Includes:** `.include` resolved against the file's directory and configured paths.
- **Sections:** which section each statement is in, for rules like "code in a data section".
- **Operand checks:** every instruction matched against `arm-isa`'s forms, with a precise message when none fit ("`add` takes a 12-bit immediate, 0 to 4095; got 5000").

`.S` files go through the C preprocessor before assembly. Phase 1 treats `#include` and `#define` lines as opaque and does not expand them; see [roadmap](roadmap.md) M3.

## Lint

**Status:** First rules done (2026-10-26), in armls and `armtool lint` ([0018](decisions/0018-lint.md)). The rules and their configuration are in [lint.md](lint.md).

Rules have an ID (`group/name`), a default severity, and a doc page. They're configured in `armtool.toml` at the project root, and can be silenced inline with `; armtool: allow(rule-id)`.

First rules, planned:

| Rule | Catches |
|---|---|
| `abi/x18-reserved` | Writing x18, which Darwin reserves for the OS |
| `abi/callee-saved` | A function writes x19 to x28, or d8 to d15, without saving and restoring them |
| `abi/frame-pointer` | A non-leaf function that doesn't set up x29 |
| `abi/stack-alignment` | sp adjusted by a value that isn't a multiple of 16 |
| `addr/adrp-pageoff` | `adrp` to `sym@PAGE` without a matching `@PAGEOFF` use of the same register |
| `addr/got-mismatch` | `@GOTPAGE` paired with `@PAGEOFF`, or the reverse |
| `flow/unbalanced-frame` | Prologue and epilogue that don't mirror each other |
| `flow/unreachable` | Code after an unconditional branch or `ret` with no label |
| `flow/missing-ret` | A function that falls through into the next one |
| `style/unused-label` | A local label nothing references |
| `style/mnemonic-case` | Mixed case mnemonics (off by default) |

Rules in the `flow` group need a control-flow graph, built per function from labels and branches. Later rules use dataflow over it: register liveness, reads of undefined registers, and syscall argument checks for `svc #0x80`.

## Language server

**Status:** v1 done (2026-10-26): diagnostics, hover, completion, definition, references, highlight, rename, symbols, semantic tokens ([0016](decisions/0016-armls-v1.md)). Since then: folding, inlay hints, code actions, formatting, navigation between files ([0029](decisions/0029-workspace-index.md)), and signature help with operand-aware completion ([0030](decisions/0030-operand-aware-editing.md)).

`armls` speaks LSP over stdio, built on `lsp-server` and `lsp-types` ([0009](decisions/0009-lsp-library.md)). It reparses a whole file on each change: assembly files are small, and a full reparse of a 10,000 line file should take under 5 ms. Incremental parsing waits until measurements say it's needed.

It negotiates UTF-8 position encoding when the client supports it, and converts to UTF-16 otherwise.

Features, in order: diagnostics, document symbols, hover, go to definition and references, completion (mnemonics, registers, directives, symbols), semantic tokens, rename, folding ranges, inlay hints (resolved immediates, `@PAGE` addresses), code actions from lint fixes, and formatting.

## Command line

**Status:** `check`, `lint`, `fmt`, `rules`, and `explain` done (2026-10-26).

`armtool lint [paths]`, `armtool check [paths]`, `armtool fmt [--check] [paths]`. Each supports `--json`. Exit codes: 0 clean, 1 findings, 2 usage error.

Client setup for Neovim, VS Code, Helix, and Zed lives in `editors/`. VS Code needs a small extension that starts `armls`; the others need only configuration.
